WBD PROJECT - BACKEND MIDDLEWARES (SIMPLE EXPLANATION)
==================================================

These are special functions that run before your main code. They check requests, add security, handle files, and manage errors. All are in backend/src/middlewares/ folder.

1. AUTH MIDDLEWARE (authMiddleware.js)
=====================================
WHAT IT DOES: Checks if users are logged in and who they are
WHEN USED: For pages that need login

MAIN FUNCTIONS:
- authenticateJWT() - Looks at the login token in request headers, checks if it's valid, adds user info to the request
- Dietitian/Organization check functions - Makes sure user has the right job/role

HOW IT WORKS:
- Gets "Bearer TOKEN" from request header
- Uses secret key to check if token is real
- If good: saves user info in req.user, lets request continue
- If bad: sends error 401 (not logged in) or 403 (no permission)

---

2. SECURITY MIDDLEWARE (securityMiddleware.js)
===============================================
WHAT IT DOES: Protects website from hackers and bad inputs
WHEN USED: On all requests to keep API safe

WHAT IT HAS:
- helmetMiddleware - Adds basic security headers to prevent attacks
- rateLimiter - Stops too many requests (max 100 per 15 minutes)
- authRateLimiter - Extra strict for login (max 5 tries per 15 minutes)
- sanitizeInput - Changes dangerous characters like < > & to safe versions
- corsHeaders - Allows requests from different websites

---

3. ERROR MIDDLEWARE (errorMiddleware.js)
=========================================
WHAT IT DOES: Catches mistakes and sends nice error messages
WHEN USED: When something goes wrong in the app

MAIN FUNCTIONS:
- AppError class - Makes all errors look the same way
- MongoDB error handlers - Fixes database error messages
- Error sender - Returns errors as JSON with right status codes

WHAT IT DOES:
- In development: Shows full error details for fixing bugs
- In production: Hides secret info but still tells user what happened
- Handles login token errors (wrong token, expired token)

---

4. LOGGER MIDDLEWARE (loggerMiddleware.js)
===========================================
WHAT IT DOES: Writes down what happens in the app
WHEN USED: On every request and when errors happen

MAIN FUNCTIONS:
- requestLogger() - Saves every request to request.txt file
- errorLogger() - Saves errors to error.txt file

WHAT IT SAVES:
- Requests: [time] GET /api/users - 192.168.1.1
- Errors: [time] ERROR GET /api/users - Database connection failed
- Files go to /logs folder

WHY USEFUL:
- See what users are doing
- Find and fix problems
- Track app usage over time

---

5. CLOUDINARY MIDDLEWARE (cloudinaryMiddleware.js)
==================================================
WHAT IT DOES: Uploads and stores pictures online
WHEN USED: When users upload photos (profile pics, blog images)

MAIN FUNCTIONS:
- uploadBlogImage - For blog post pictures
- uploadUserPhoto - For user profile pictures
- uploadToCloudinary() - Sends file to cloud storage
- deleteFromCloudinary() - Removes file from cloud

WHAT IT DOES:
- Uses memory to hold file temporarily
- Only allows picture files (jpg, png, etc.)
- Makes pictures smaller and better quality
- Saves to Cloudinary cloud service

---

6. UPLOAD MIDDLEWARE (uploadMiddleware.js)
===========================================
WHAT IT DOES: Handles document uploads (not pictures)
WHEN USED: For PDFs, certificates, medical reports

WHAT IT HAS:
- Memory storage - Holds files in computer memory temporarily
- File size check - Max 20MB per file
- File type check - Allows PDFs, docs, etc.
- Single/multiple upload support

USED FOR:
- Lab reports (PDF files)
- Certificates (PDF or images)
- ID documents
- Medical prescriptions

---

7. BLOG MIDDLEWARE (blogMiddleware.js)
=======================================
WHAT IT DOES: Checks who can create/edit blog posts
WHEN USED: For blog writing and editing pages

MAIN FUNCTIONS:
- verifyBlogAuth() - Checks login token and user role for blog access
- blogAuthorMiddleware() - Makes sure only the writer can change their own blog

WHAT IT CHECKS:
- User must be logged in to write blogs
- Only blog owner can edit/delete their posts
- Admin users can do everything

---

8. STATUS MIDDLEWARE (statusMiddleware.js)
===========================================
WHAT IT DOES: Checks if professionals are verified
WHEN USED: For pages that need verified users (doctors, companies)

MAIN FUNCTIONS:
- statusMiddleware() - Checks login and verification status
- Dietitian/Organization status checkers
- Returns verification info

WHAT IT PROTECTS:
- Stops unverified users from using special features
- Only verified doctors can access certain pages
- Shows document verification progress

---

9. SUBSCRIPTION MIDDLEWARE (subscriptionMiddleware.js)
=======================================================
WHAT IT DOES: Controls what features users can use based on their plan
WHEN USED: For paid features and limits

PLANS AVAILABLE:
- Free - Basic features only
- Basic - More features
- Premium - Almost everything
- VIP - All features plus extras

WHAT IT CONTROLS:
- Diet plans access (weight loss, fitness, etc.)
- How many blogs you can read
- How many doctor bookings allowed
- Meal plan viewing limits

MAIN FUNCTIONS:
- checkSubscription() - Verifies user's payment plan
- Feature blockers - Stops access to locked features
- Plan trackers - Shows what's available per plan
- Expiry checker - Handles when plans end

---

HOW MIDDLEWARES RUN IN ORDER (in server.js)
==========================================

1. SECURITY FIRST (protects everything):
   - Error catcher (wraps everything)
   - Helmet (security headers)
   - Rate limiter (stops spam)
   - CORS (allows other websites)
   - Body parsers (reads request data)
   - Input cleaner (removes bad code)

2. LOGGING:
   - Request logger (writes down requests)

3. CHECK LOGIN ON PROTECTED PAGES:
   - Auth middleware on login-required routes
   - Blog auth on blog pages
   - Status check on verification pages
   - Subscription check on paid features

4. FILE UPLOADS (when needed):
   - Cloudinary (for pictures)
   - Upload handler (for documents)

5. ERROR HANDLING AT END:
   - Error logger (saves error details)
   - Error sender (tells user what happened)
